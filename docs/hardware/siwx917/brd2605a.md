The BRD2605A dev kit is Silicon Labs' official SiWx917 Wi-Fi 6 & Bluetooth LE Dev Kit (SiWx917-DK2605A), with TuyaOpen board support. The on-board SEGGER J-Link debugger covers flashing and logs over a single USB Type-C cable with no extra wiring — the most convenient part compared to the AI dev kit. It has no display, and audio is capture-only through the on-board MEMS microphone.

![Silicon Labs BRD2605A evaluation board](/img/hardware/siwx917/brd2605a.png)

## Software build configuration

The board configuration file defines the configuration parameters for peripheral drivers, pin mapping, the BSP package, and third-party libraries. Building with the kit's preconfigured board file saves most of the hardware adaptation effort.

:::tip Want to develop new peripherals?

- **To add peripherals, write the drivers at the application layer.** BSP drivers mainly serve the peripherals fixed on the board.

- **Recommended:** treat the initial configuration file as the **board base template** and extend it for your own development.
:::

## Hardware overview

The kit shares its toolchain with Silicon Labs' official flow: the SDK board definition comes from the `brd2605a` configuration shipped inside the WiseConnect SDK, and the on-board debugger exposes both J-Link SWD and a virtual COM port (VCOM). The board also carries temperature/humidity, ambient-light, and 6-axis sensors plus a Qwiic connector. Audio is capture-only (MEMS stereo microphone); there is no speaker and no display.

## Kit highlights

- SiWG917M111MGTBA module (Wi-Fi 6 2.4 GHz + Bluetooth LE, 2.4 GHz ceramic chip antenna)
- ARM Cortex-M4 @ 180 MHz
- 8 MB flash + 320 kB on-chip RAM
- On-board SEGGER J-Link + virtual COM port (VCOM) — one USB Type-C cable for flashing and logs
- Temperature/humidity, ambient-light, and 6-axis inertial sensors
- MEMS stereo microphone
- RGB LED and two buttons (BTN0/BTN1)
- Two-row EXP1A/EXP1B expansion header, Qwiic connector

## Pin definitions

### Breakout headers (EXP1A / EXP1B, two rows)

Expansion signals are brought to a 26-pin 2.54 mm **dual-row header**, silkscreened **EXP1A (odd) / EXP1B (even)**, exposing module GPIOs, the SDIO/IMU-SPI interfaces, the VCOM UART, I2C buses, and power (nets verified against the schematic netlist):

#### EXP1A (odd row, 1–25)

| Pin | Signal | Pin | Signal |
|-----|--------|-----|--------|
| 1 | VMCU | 15 | SENSOR_I2C (SCL) |
| 3 | SDIO CLK | 17 | BOARD_ID_I2C (via R142, 4.7 kΩ) |
| 5 | SDIO CMD | 19 | BOARD_ID_I2C (via R143, 4.7 kΩ) |
| 7 | SDIO D0 | 21 | GPIO_6 |
| 9 | SDIO D1 | 23 | GPIO_10 |
| 11 | SDIO D2 | 25 | GPIO_12 |
| 13 | SDIO D3 | | |

#### EXP1B (even row, 2–26)

| Pin | Signal | Pin | Signal |
|-----|--------|-----|--------|
| 2 | VMCU | 16 | SENSOR_I2C (SDA) |
| 4 | IMU SPI CLK | 18 | NC |
| 6 | IMU SPI CS | 20 | NC |
| 8 | IMU SPI MOSI | 22 | GPIO_11 |
| 10 | IMU SPI MISO | 24 | GPIO_7 |
| 12 | VCOM TX | 26 | GND |
| 14 | VCOM RX | | |

Notes:

- **SENSOR_I2C** is the bus of the on-board sensors; **BOARD_ID_I2C** is the board-identification I2C (routed through 4.7 kΩ resistors). Both can serve as general-purpose I2C when you expand the board.
- The six **SDIO** lines and four **IMU SPI** lines expose chip interfaces on the header; if you don't attach an SDIO device, those 10 pins work as GPIOs.
- **VCOM** wires the debugger's virtual UART straight to the header; mind the overlap with the USB virtual COM when attaching serial devices.

Debugging does not consume the expansion header: the on-board J-Link (SWD) and VCOM work directly over USB Type-C with no wiring. For background, see the [UG581 user guide](https://www.silabs.com/documents/public/user-guides/ug581-brd2605a-user-guide.pdf).

### Board-level pins (application-visible)

From [`BRD2605A/Kconfig`](https://github.com/tuya/TuyaOpen/blob/master/boards/SIWX917/BRD2605A/Kconfig) and `brd2605a_board.c`. For the TUYA-GPIO-to-pad conversion, see the [AI dev kit page](siwx917-ai-dev-kit#gpio-number-conversion).

| Function | Kconfig | TUYA GPIO | Chip pad | Registered name |
|----------|---------|-----------|----------|-----------------|
| Button 1 | `BOARD_SW1_PIN` | 49 | HP 49 | `SW1` |
| Button 2 | `BOARD_SW2_PIN` | 2 | UULP 2 | `SW2` |
| Button 3 | `BOARD_SW3_PIN` | 3 | UULP 3 | `SW3` |
| LED R | `BOARD_LEDR_PIN` | 50 | HP 50 | `LEDR` |
| LED G | `BOARD_LEDG_PIN` | 51 | HP 51 | `LEDG` |
| LED B | `BOARD_LEDB_PIN` | 15 | HP 15 | `LEDB` |

Buttons use `LEVEL_LOW` + `PULLUP` + `TIMER_SCAN_MODE`; LEDs use `LEVEL_LOW` + `PUSH_PULL`.

#### Microphone enable

| Signal | TUYA GPIO | Chip pad | Configuration |
|--------|-----------|----------|---------------|
| MIC_EN | `TUYA_GPIO_NUM_0` | UULP 0 | `PUSH_PULL` / `OUTPUT` / default high |

#### Log UART

ULP_UART, TX = ULP 11 = TUYA 41, RX = ULP 9 = TUYA 39, 115200 8N1; it lands on the on-board J-Link VCOM.

:::warning[Running your_chat_bot on BRD2605A]
`your_chat_bot` looks up the chat button by the hard-coded name `ai_chat_button`, while this board registers it as `SW1` by default. Before running the demo, change the default of `BOARD_SW1_NAME` in `boards/SIWX917/BRD2605A/Kconfig` to `ai_chat_button` (the option has no prompt, so setting it in `.config` does not take effect).
:::
