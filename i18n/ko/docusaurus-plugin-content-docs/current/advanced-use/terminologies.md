## TuyaOpen과 TuyaOS 비교
### TuyaOpen
TuyaOpen은 성숙한 상용 IoT 시스템인 TuyaOS를 기반으로 구축된 AIoT 산업용 오픈 소스 개방형 개발 프레임워크입니다. 크로스 플랫폼 호환성, 크로스 시스템 지원, 모듈성, 보안 준수 등 핵심 기능을 계승했으며, 전 세계 수십억 대의 디바이스와 수백만 명의 사용자를 통해 검증되었습니다.

TuyaOpen은 엣지 측 AI 추론 엔진을 통합하고 Tuya Cloud Agent Hub를 지원하며 엣지-클라우드 융합을 통해 멀티모달 AI 기능을 제공합니다. 개발자는 규정을 준수하는 국내 대규모 모델(예: DeepSeek, Qwen, Doubao)에 원활하게 접근하거나 글로벌 주요 AI 서비스(예: ChatGPT, Claude, Gemini)를 유연하게 통합할 수 있습니다. 다양한 도구 생태계를 활용해 텍스트/음성 대화, 이미지 생성, 비디오 생성 등 여러 AI 기능을 구현할 수 있습니다.

또한 TuyaOpen은 업계의 주요 오픈 소스 하드웨어 및 소프트웨어 생태계를 지원하므로 개발자가 어떤 칩이나 개발 보드에도 프로젝트를 쉽게 포팅하고 배포할 수 있습니다. 이를 통해 AI 기술을 활용한 혁신을 가속하고 제품 개발 주기를 단축합니다.

### TuyaOS
TuyaOS는 IoT 애플리케이션을 위한 분산형 크로스 플랫폼 운영 체제로, RTOS, Linux, Non-OS 커널 전반의 연결성과 시나리오를 지원합니다. TuyaOS Kernel과 풍부한 개발 구성 요소를 기반으로 칩 플랫폼, 시스템, 통신 프로토콜, 애플리케이션 소프트웨어마다 달랐던 개발 경험의 차이를 줄여 개발자가 비즈니스 혁신과 개발에만 집중할 수 있도록 합니다. "한 번 작성하고 어디서나 배포"를 통해 TuyaOS는 글로벌 배포와 규정 준수를 보장합니다.

아키텍처는 계층형 플러그 앤 플레이 구성 요소 설계를 사용하므로 칩 리소스와 애플리케이션 시나리오에 따라 맞춤형 개발 프레임워크를 생성할 수 있습니다. Tuya의 독점 디바이스 모델과 자체 개발 소프트 버스를 통해 TuyaOS로 개발한 제품은 통신 프로토콜과 관계없이 상호 연결할 수 있습니다.

## 하드웨어 개발
| 용어 | 설명 |
|------|-------------|
| MCU | MCU는 하나의 집적 회로에 구현된 소형 컴퓨터로, 집적도가 높고 기능이 풍부하며 응답 속도와 신뢰성이 높고 적용 범위가 넓습니다. MCU를 탑재한 디바이스에는 제품 기능을 정의하는 자체 제어 보드가 있습니다. 네트워크 모듈은 제어 보드에 연결되어 네트워크 연결을 구현합니다. |
| SoC | SoC는 system on a chip의 약어입니다. SoC 디바이스에는 MCU가 없으며 제어 프로그램은 SoC 또는 모듈에 기록됩니다. |
| 네트워크 모듈 | 네트워크 모듈은 임베디드 전자 시스템을 네트워크에 연결하는 구성 요소입니다. 각 모듈은 임베디드 시스템과 네트워크를 연결하는 회로 모듈입니다. Tuya는 현재 Wi-Fi 모듈, GPRS 모듈, Bluetooth mesh 모듈, Wi-Fi 및 Bluetooth Low Energy(LE) 콤보 모듈, Zigbee 모듈, Sub-GHz 모듈, NB-IoT 모듈 등 다양한 방식의 네트워크 연결 모듈을 제공합니다. |
| DP | 데이터 포인트(DP)는 스마트 디바이스의 기능을 나타냅니다. Tuya는 각 기능을 데이터 포인트로 추상화합니다. DP는 Boolean, enumeration, integer 등 여러 데이터 형식으로 정의되며 읽기 및 쓰기 속성을 가집니다. 예를 들어 2구 스위치에는 두 개의 Boolean DP가 있고 각 DP는 True 또는 False 값을 가질 수 있으며 읽고 쓸 수 있습니다. 읽기는 스위치의 현재 값을 가져오는 것이고 쓰기는 현재 값을 변경하는 것입니다. |
| DPID | DP ID는 통신 프로토콜에서 DP 이벤트의 ID를 나타냅니다. |
| Device ID | 각 디바이스를 고유하게 식별하는 식별자입니다. |
| DPCode | DP 이벤트의 고유 식별자입니다. 대부분의 경우 서로 다른 통신 프로토콜에서 동일한 DP 이벤트의 DPCode는 같습니다. |
| AuthKey | 플랫폼에서 발급하는 디바이스 인증 키입니다. AuthKey는 product ID(PID) 및 universally unique identifier(UUID)와 강하게 연결됩니다. 참고: 이 매개변수는 매우 중요하며 디바이스 인증에 사용됩니다. 값을 안전하게 보관하세요. |


## 통신 및 프로토콜
| 용어 | 설명 |
|------|-------------|
| Bluetooth | Bluetooth 기술은 근거리 무선 음성 및 데이터 통신을 지원하도록 설계된 개방형 글로벌 사양입니다. 저비용 단거리 무선 연결을 통해 고정 디바이스와 모바일 디바이스 간에 데이터를 교환합니다. 따라서 휴대용 디바이스와 기타 디지털 디바이스는 전선이나 케이블 없이 무선으로 인터넷에 연결할 수 있습니다. |
| P2P | 피어 투 피어(P2P) 네트워킹은 작업 또는 워크로드를 피어 사이에 분할하는 분산 애플리케이션 아키텍처입니다. P2P는 애플리케이션 계층에서 피어 컴퓨팅 모델로 구성되는 네트워크 또는 네트워크 유형입니다. |
| RTP | 실시간 전송 프로토콜(RTP)은 종단 간(E2E) 실시간 데이터 전송을 위한 네트워크 프로토콜입니다. 멀티캐스트 또는 유니캐스트 네트워크를 통해 대화형 오디오, 비디오 또는 아날로그 데이터를 전달하는 데 사용됩니다. RTP는 전화, 화상 회의, TV 서비스, 웹 기반 푸시 투 토크 등 스트리밍 미디어를 사용하는 통신 및 엔터테인먼트 시스템에서 널리 사용됩니다. |
| Socket | 소켓은 네트워크에서 실행되는 두 프로그램 사이의 양방향 통신 링크의 종단점입니다. 통신 링크에는 포트 번호에 바인딩된 소켓이 두 개 이상 필요합니다. 본질적으로 소켓은 TCP/IP 캡슐화에서 네트워크 개발을 위해 프로그래머에게 제공되는 애플리케이션 프로그래밍 인터페이스(API)입니다. |
| MQTT | Message Queuing Telemetry Transport(MQTT)는 IBM이 개발한 발행-구독 기반 메시징 프로토콜입니다. MQTT는 모든 플랫폼을 지원하며 대부분의 IoT 제품을 외부 환경에 연결할 수 있습니다. 센서와 브레이크의 통신 프로토콜로 사용됩니다. |

## 하드웨어
| 용어 | 설명 |
|------|-------------|
| I/O pin 및 GPIO | 모듈의 핀, 즉 입력/출력 채널을 나타냅니다. GPIO는 범용 입력/출력 핀을 의미합니다. |
| Pin | 핀은 집적 회로(칩)의 내부 회로를 외부 회로에 연결합니다. 칩의 모든 핀은 칩의 인터페이스를 구성합니다. |
| AC-DC power module | AC-DC 전원 모듈은 건전지, 축전지, DC 발전기 등을 포함해 회로에 일정한 전류를 제공합니다. |
| LDO | 저손실 선형 레귤레이터(LDO)는 입력 전압이 출력 전압에 매우 가까워도 출력 전압을 조절할 수 있는 DC 선형 전압 레귤레이터입니다. |
| Development board | 개발 보드는 임베디드 시스템 개발을 지원하는 회로 기판입니다. |
| PCB | 인쇄 회로 기판(PCB)은 비전도성 기판에 적층된 하나 이상의 구리 시트 층에서 식각한 전도성 트랙, 패드 및 기타 요소를 사용해 전자 부품을 기계적으로 지지하고 전기적으로 연결합니다. |
| PCBA/PCB'A | 인쇄 회로 기판 조립(PCBA)은 표면 실장 기술(SMT)을 사용해 빈 PCB에 부품을 배치하고, 스루홀 방식으로 DIP(dual in-line package)를 실장하는 전체 과정입니다. 중국 개발자는 일반적으로 PCBA를 사용하고 유럽과 미국에서는 표준 표기인 PCB'A를 사용합니다. |
| Antenna interface | 안테나는 무선 연결을 통해 신호를 수신하고 전송하는 하드웨어 구성 요소입니다. 대표적으로 PCB 안테나, 헬리컬 안테나, 세라믹 칩 안테나, I-PEX 커넥터가 있는 FPC 안테나, 막대형 구리 안테나가 있습니다. |
| Antenna gain | 안테나 이득은 동일한 입력 전력 조건에서 같은 공간 지점의 실제 안테나 신호 전력 밀도와 이상적인 방사 소자의 전력 밀도 비율입니다. 안테나 이득은 안테나가 입력 전력을 특정 방향으로 향하는 전파로 얼마나 잘 변환하는지를 정량적으로 나타냅니다. |
| Receiving sensitivity | 수신 감도는 수신기가 복조할 수 있는 최소 신호 레벨을 나타냅니다. 이 값은 음수입니다. 값이 작을수록 수신기 성능이 좋습니다. |

## 임베디드 프로그래밍
| 용어 | 설명 |
|------|-------------|
| SDK | 소프트웨어 개발 키트(SDK)는 소프트웨어 개발에 필요한 문서, 예제, 도구를 포함합니다. Tuya는 개발자가 시스템이나 언어를 사용할 수 있도록 무료 SDK를 제공합니다. |
| Firmware | 펌웨어는 삭제 가능한 프로그램 가능 읽기 전용 메모리(EROM) 또는 전기적으로 삭제 가능한 프로그램 가능 읽기 전용 메모리(EEPROM)에 기록되는 프로그램입니다. 펌웨어는 CD-ROM 및 CD-R과 같은 디바이스에 내장된 프로그램을 구동하며, 표준 디바이스 드라이버를 기반으로 운영 체제가 디바이스를 구동할 수 있도록 합니다. 펌웨어는 시스템의 가장 기본적인 하위 계층 작업을 수행하는 소프트웨어입니다. |
| OTA | OTA 업데이트는 연결된 스마트 디바이스에 새 소프트웨어, 펌웨어 또는 기타 데이터를 무선으로 전달하는 방식입니다. 펌웨어 업데이트는 무선 또는 유선으로 진행할 수 있습니다. FOTA(firmware over-the-air)는 무선 업데이트 방식입니다. |
| Serial port | 시리얼 포트는 일반적으로 COM 포트라고도 하며 시리얼 통신 방식을 사용하는 확장 포트입니다. 시리얼 포트는 한 번에 1비트씩 전송합니다. 통신 경로가 단순한 것이 특징입니다. 예를 들어 한 쌍의 전송 케이블(전화선 한 쌍)은 두 시리얼 포트 간 양방향 통신을 가능하게 해 통신 비용을 크게 줄입니다. 시리얼 포트는 주로 장거리 통신에 사용되지만 전송 속도는 낮습니다. |
| UART | 범용 비동기 송수신기(UART)는 병렬 입력 신호를 직렬 출력 신호로 변환하는 컴퓨터 하드웨어 디바이스입니다. UART는 일반적으로 독립 모듈 칩이나 마이크로프로세서에 통합된 주변 장치 등 다른 통신 인터페이스 디바이스에 통합됩니다. |
| Serial communication protocol | 시리얼 통신 프로토콜은 시리얼 포트가 비트 단위로 데이터를 송수신하도록 합니다. 시리얼 통신은 바이트 단위로 데이터를 교환하는 병렬 통신보다 느리지만, 하나의 링크로 데이터를 전송하고 다른 링크로 동시에 데이터를 수신할 수 있습니다. 일반적인 시리얼 통신 프로토콜에는 RS-232, RS-422, RS-485가 있습니다. |
| RTC | 실시간 클록(RTC)은 시스템 타이머와 독립적인 디바이스입니다. 시스템 클록을 설정하고 알람 또는 주기적 타이머를 제공하는 데 사용됩니다. |
| Arduino | Arduino는 세계에서 가장 인기 있는 오픈 소스 하드웨어 제품 중 하나이자 뛰어난 하드웨어 개발 플랫폼이며 하드웨어 개발의 흐름을 이끌고 있습니다. Arduino는 간단한 개발 방식을 제공하므로 창의적인 아이디어와 구현에 더 집중하고 프로젝트 개발을 빠르게 완료하며 학습 비용과 개발 주기를 줄일 수 있습니다. |
| ADC | ADC는 Analog-to-Digital Converter의 약어입니다. 아날로그 신호를 디지털 신호로 변환하는 디바이스입니다. 임베디드 시스템에서는 온도, 습도, 조도 센서와 같은 아날로그 센서의 값을 읽는 데 일반적으로 사용됩니다. |
| GPIO | GPIO는 General-Purpose Input/Output의 약어입니다. 외부 디바이스를 제어하는 임베디드 시스템의 기본 인터페이스로 입력 또는 출력 모드로 설정할 수 있습니다. |
| PWM | PWM은 Pulse Width Modulation의 약어입니다. 신호의 듀티 사이클을 조절해 출력 전력을 제어하는 기술로 모터 속도, LED 밝기 등을 제어하는 데 일반적으로 사용됩니다. |
| Timer | 타이머는 특정 시간 간격으로 작업을 실행하는 데 사용됩니다. 임베디드 시스템에서는 정밀한 지연을 만들고 시간 간격을 측정하며 주기적 이벤트를 생성하는 데 일반적으로 사용됩니다. |
| Sleep | 슬립 모드는 에너지를 절약하기 위해 디바이스가 대부분의 기능을 일시 중지하는 저전력 상태입니다. 임베디드 시스템에서는 배터리 수명을 연장하는 데 일반적으로 사용됩니다. |
| SPI | SPI는 Serial Peripheral Interface의 약어입니다. 센서와 메모리 같은 외부 디바이스를 마이크로컨트롤러에 연결하는 데 일반적으로 사용되는 동기식 시리얼 통신 프로토콜입니다. |
| I2C | I2C는 Inter-Integrated Circuit의 약어입니다. 센서와 메모리 같은 외부 디바이스를 마이크로컨트롤러에 연결하는 데 일반적으로 사용되는 동기식 시리얼 통신 프로토콜입니다. |
| I2S | I2S는 Inter-IC Sound의 약어입니다. 오디오 데이터 전송에 사용되는 시리얼 통신 프로토콜로 스피커와 마이크 같은 오디오 디바이스를 연결하는 데 일반적으로 사용됩니다. |
| DVP | DVP는 Digital Video Port의 약어입니다. 디지털 비디오 신호를 전송하는 인터페이스로 카메라와 같은 비디오 디바이스를 연결하는 데 일반적으로 사용됩니다. |


## 클라우드 개발
| 용어 | 설명 |
|------|-------------|
| Tuya Cloud | Tuya의 글로벌 배포를 위한 디바이스 관리 허브입니다. 이 허브는 southbound 인터페이스를 통해 Powered by Tuya(PBT) 디바이스에 연결하고 northbound 인터페이스를 통해 IoT 애플리케이션과 통신합니다. |
| Cloud project | 데이터 저장의 단위입니다. 다양한 개발 권한과 데이터는 클라우드 프로젝트를 기준으로 관리됩니다. |
| Cloud service | 특정 시나리오의 기능을 구현하기 위해 호출할 수 있는 OpenAPI의 모음입니다. |
| Link | 클라우드 통합 중에 기존 앱, PID 및 기타 비즈니스 데이터를 클라우드 프로젝트와 연결할 수 있습니다. |
| accessId 및 accessKey | 클라우드 애플리케이션 키 쌍이라고도 합니다. 플랫폼의 클라우드 개발 섹션에서 클라우드 애플리케이션을 생성하면 백그라운드에서 accessId와 accessKey가 자동으로 생성됩니다. |

## 공통 용어
| 용어 | 설명 |
|------|-------------|
| PID | product ID의 약어입니다. 플랫폼에서 생성한 각 제품에는 고유한 PID가 할당됩니다. |
| UUID | Universally Unique Identifier의 약어입니다. Tuya 스마트 제품 개발에서 UUID는 디바이스의 고유 식별 ID로 사용됩니다. AuthKey는 디바이스를 클라우드에 등록하는 데 필요한 인증 키로 UUID와 일대일 대응 관계를 이룹니다. UUID의 길이는 20자이고 AuthKey는 32자입니다. 반복적인 활성화 또는 네트워크 구성 작업과 관계없이 UUID는 변경되지 않습니다. PID, UUID, AuthKey를 흔히 "디바이스 트리플렛"이라고 합니다. |
| DeviceID | 디바이스가 활성화되고 네트워크 연결을 구성할 때마다 클라우드가 할당하는 ID입니다. 네트워크 구성 후 계정 및 앱과 연결된 실제 사용자 디바이스 데이터에 연결됩니다. 특정 시나리오(예: 사용자가 앱의 디바이스 속성 페이지에서 오른쪽 상단의 "바인딩 해제 및 데이터 삭제"를 누르는 경우)에는 DeviceID가 변경될 수 있으며 재구성/재활성화가 필요합니다. |
| API | 애플리케이션 프로그래밍 인터페이스(API)는 애플리케이션과 개발자가 소프트웨어 또는 하드웨어를 기반으로 라이브러리에 액세스할 수 있도록 미리 정의된 함수입니다. |
| Cloud API | Cloud API를 사용하면 클라우드 서비스 제공업체가 제공하는 서비스를 클라우드 애플리케이션 프로그래밍 인터페이스로 사용할 수 있습니다. |
