디바이스 디버깅은 시리얼 포트를 통해 디바이스 로그를 수집하여 문제를 추적하고 동작을 확인하는 기능입니다. [TuyaOpen](https://github.com/tuya/TuyaOpen) 펌웨어를 플래시한 후 시리얼 로그는 디바이스에서 실제로 수행되는 작업을 확인하는 기본 수단입니다.

:::info
TuyaOpen이 지원하는 IoT 및 AI+IoT 칩은 J-Link 디버깅 도구를 지원하지 않습니다. 대신 시리얼 포트 로그를 사용하세요.
:::

## 필요한 항목
시작하기 전에 다음을 준비하세요.

### 하드웨어
- [TuyaOpen 호환 개발 보드 또는 모듈](../hardware/index.md#hardware-platforms)
- USB 데이터 케이블 또는 USB-to-TTL 변환기

### 디버깅 도구
다음 시리얼 디버깅 도구 중 하나를 선택하세요.

- [Tuya 범용 시리얼 도구](https://www.tuyaopen.ai/zh/tyutool): 그래픽 인터페이스로 쉽게 조작할 수 있습니다.
- TuyaOpen `tos` 명령줄 도구: 명령줄 기반으로 유연한 옵션을 제공합니다.
- 타사 도구: SSCOM, MobaXterm, PuTTY 등

## 시리얼 파라미터 설정
연결하기 전에 칩의 시리얼 포트와 baud rate를 확인하세요. 잘못된 값을 사용하면 읽을 수 있는 로그가 출력되지 않습니다.

| 칩 모델 | 시리얼 포트 | Baud rate | 비고 |
|---------|---------|--------|------|
| Ubuntu | - | - | Ubuntu 및 기타 Linux 호스트에서 직접 실행 |
| T2 | Uart2 | 115200 | - |
| T3 | Uart1 | 460800 | - |
| T5AI | Uart1 | 460800 | - |
| ESP32/ESP32C3/ESP32S3 | Uart0 | 115200 | - |
| LN882H | Uart1 | 921600 | - |
| BK7231N | Uart2 | 115200 | - |

:::tip
올바른 시리얼 포트와 baud rate를 선택하세요. 그렇지 않으면 로그가 출력되지 않을 수 있습니다.
:::

## 로그 수집
사용 방식에 맞는 도구를 선택하세요.

### 방법 1: Tuya 범용 시리얼 도구
그래픽 도구는 친숙한 인터페이스와 완전한 기능을 제공하므로 대부분의 사용자에게 권장됩니다. [GUI - tyutool 그래픽 도구](../tos-tools/tools-tyutool.md)를 참고하세요.

### 방법 2: `tos` 명령줄 도구
명령줄 사용에 익숙하고 더 유연한 옵션이 필요하면 이 방법을 사용하세요. [tos monitor 명령](../tos-tools/tos-guide.md#monitor)을 참고하세요.

### 방법 3: 타사 시리얼 도구
SSCOM, MobaXterm 또는 PuTTY 같은 다른 시리얼 도구를 사용하려면 위의 시리얼 파라미터로 설정하고 해당 도구의 문서를 따르세요.

## 디버깅 팁
- **연결 확인**: 하드웨어 연결이 올바르고 시리얼 케이블이 손상되지 않았는지 확인하세요.
- **파라미터 일치**: 위 표에 나온 시리얼 포트와 baud rate를 정확히 설정하세요.
- **로그 분석**: 시작 로그, 오류 메시지 및 예상하지 못한 출력을 중점적으로 확인하세요.
- **문제 기록**: 발견한 문제와 적용한 해결 방법을 진행하면서 기록하세요.

:::note
시리얼 출력이 없으면 하드웨어 연결, 시리얼 파라미터 설정 및 드라이버 설치를 확인하세요.
:::
