## TuyaOpen IDE란 무엇인가 {/* #what-is */}
TuyaOpen IDE는 **VS Code** 또는 **Cursor** 안에서 실행되는 AI 시대의 임베디드 개발 환경입니다. 하드웨어 코드를 처음부터 작성하는 대신 원하는 디바이스를 **자연어**로 설명하면 AI Agent가 프로젝트를 생성하고 펌웨어를 작성하며 클라우드 기능을 구성합니다.

이러한 방식을 **Vibe Coding**이라고 합니다. 원하는 동작의 “분위기”를 설명하면 AI가 실행 가능한 프로젝트로 변환합니다.

한 문장으로 말하면, 기존 임베디드 개발은 *직접 코드를 작성하고 보드가 실행하는 방식*이고 TuyaOpen IDE는 *말하면 AI가 코드를 작성하고 보드가 실행하는 방식*입니다.

### 5분 안에 할 수 있는 작업 {/* #what-it-can-do */}
- **한 문장으로 완전한 IoT 프로젝트 생성** — 예: “앱으로 제어하는 LED를 만들어 줘.”
- **펌웨어 자동 생성** — T2, T3, T5 및 ESP32와 같은 칩에 맞게 생성합니다.
- **Tuya Cloud 기능 구성** — 네트워킹, 앱 제어 및 AI 음성을 구성합니다.
- **하나의 프로젝트에서 세 영역 연결** — 펌웨어, 클라우드 Agent 및 휴대폰 앱을 함께 연결합니다.

## 핵심 기능 {/* #core-features */}
| 기능 | 제공하는 것 |
| --- | --- |
| **Vibe Coding** | 모든 줄을 직접 작성하지 않고 자연어로 AI Agent를 구동합니다. |
| **하드웨어 컨텍스트 인식** | 사용 중인 보드와 핀을 인식하므로 생성한 코드가 바로 실행됩니다. |
| **세 영역 통합** | 하나의 워크스페이스에서 펌웨어, 클라우드 Agent 및 앱을 함께 개발합니다. |
| **칩 간 지원** | 하나의 툴체인으로 T2, T3, T5, ESP32, ESP32-C3 등을 지원합니다. |

## 기존 IoT 개발과의 차이 {/* #vs-traditional */}
| | 기존 임베디드 개발 | TuyaOpen IDE(Vibe Coding) |
| --- | --- | --- |
| **시작 방법** | 프로젝트를 만들고 툴체인을 구성한 뒤 레지스터 코드를 작성합니다. | 원하는 것을 한 문장으로 설명합니다. |
| **코드 출처** | 모두 직접 작성하거나 복사하고 수정합니다. | AI Agent가 생성하고 개발자가 검토·수정합니다. |
| **클라우드 기능** | 클라우드 API를 직접 통합합니다. | IDE가 Tuya Cloud를 구성합니다. |
| **앱** | 별도 도구로 개발합니다. | 세 영역 중 하나로 함께 생성됩니다. |
| **진입 장벽** | 임베디드, 네트워킹 및 클라우드 지식이 필요합니다. | 요구 사항을 설명할 수 있으면 시작할 수 있습니다. |

## 대상 사용자 {/* #who-it-is-for */}
- **완전한 초보자** — 스마트 하드웨어를 만들고 싶지만 아직 코드를 작성하지 못하는 메이커와 학생은 Vibe Coding으로 시작합니다.
- **임베디드 엔지니어** — 반복 코드를 줄이고 빠르게 개발하려면 Agent가 기본 구조를 생성하게 한 뒤 다듬습니다.
- **일반적인 시나리오** — 스마트 조명, AI 음성 비서, 로봇 제어, 센서-클라우드 애플리케이션

## 지원 보드 및 칩 {/* #supported-boards */}
TuyaOpen IDE는 TuyaOpen Framework가 지원하는 모든 칩을 지원합니다.

| 칩 계열 | 일반적인 보드 | 용도 |
| --- | --- | --- |
| **T5** | T5 AI Core / T5 AI Board | AI 및 네트워킹, 권장 메인라인 |
| **T3** | T3 LCD DevKit | 디스플레이 및 네트워킹 |
| **T2** | T2-U | 보급형 네트워킹 |
| **ESP32** 계열 | ESP32 / ESP32-C3 / ESP32-S3 | 범용 MCU |
| LN882H / BK7231N / GD32 | 벤더 보드 | 특정 시나리오 |

:::note
전체 보드 선택 매트릭스는 [하드웨어 플랫폼](/docs/hardware)을 참고하세요.
:::
